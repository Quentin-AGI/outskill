## 七项逐条核验

### 1. EPUB 摘录、版本、资源上限与覆盖备份：通过，带残余风险

已确认：

- CLI 已删除 `read`，仅保留 `excerpt`；
- `--anchor` 为必填，`MAX_EXCERPT_CHARS = 800`，输出是结构化 JSON；
- 仅允许 `.html/.xhtml/.htm`；缺失锚点、非 HTML、超过 800 均拒绝；
- EPUB 2 NCX 与 EPUB 3 nav 合成样本均通过；通过 `container.xml → OPF → manifest/spine/nav` 定位；
- 文件哈希流式计算；成员数、单成员大小、总未压缩大小、标记内容大小、压缩比均有限制；
- index 已存在时默认拒绝，`--force` 会先生成唯一备份，新索引在 POSIX 下设为 `0600`。

残余问题：

- **P1**：`write_index()` 未拒绝目录。`--force` 可把任意现有目录整体移动到备份名，然后以同名文件替代。应要求现有目标必须是普通文件，拒绝目录、设备和软链接；备份与新写入最好都使用原子暂存，并校验备份权限。
- **P2**：`--anchor ""` 没有入口级非空校验；构造含 `id=""` 的 HTML 时解析器会把空字符串当命中锚点。应要求 `anchor.strip()` 非空并设置合理长度上限。
- **P2**：smoke test 验证了异常压缩比，但没有分别构造成员数、单成员、累计大小和 8 MB 标记上限的边界样本；实现中已有检查，后续可补轻量单元测试。

### 2. 私有工作区、共享边界与主目录扫描：部分通过，存在 P0

已确认：

- 正常新建工作区实测根目录为 `0700`，企业文件为 `0600`；脚本设置 `umask(077)` 并在 POSIX 上逐项复核；
- 非 POSIX 环境不会声称已经私有，而会要求管理员配置 ACL；
- README 和协议明确区分团队案例与个人档案，禁止递归放宽个人目录，建议成员使用独立 OS 账号/私有根；
- 运行协议只允许用户明确路径或 `KOTLER_MARKETING_WORKSPACE`，明确禁止扫描主目录；工作区脚本也只检查指定目标，没有发现主目录枚举。

**P0 回归失败**：`destination` 在一开始被 `resolve()`，而内部计划路径没有做“仍位于目标根内且不是软链接”的逐项检查。`--merge` 因而会沿 `company-profile`、`cases`、`people` 等内部软链接写到外部位置，并对外部目标执行 `chmod`。修复建议：

- 在写入前以 `lstat` 检查目标根到每个计划项的所有路径组件，任何软链接均拒绝；
- 对每个最终目标做解析后 containment 检查，必须仍位于已批准的 workspace root；
- `--merge` 只能合并带有效 `.kotler-workspace.json` 标记且权限符合预期的工作区；
- 增加“内部目录软链接、悬空文件软链接、标记文件软链接”三个测试，断言无外部文件与权限变化。

### 3. 安装递归/软链接、暂存与原子切换：通过，带低级残余风险

已确认：

- `within(destination, SOURCE_DIR)` 拒绝目标等于源或位于源内；
- 目标本身为软链接时拒绝；一般软链接和指回源的软链接均实际返回非零；
- 复制发生在目标根同文件系统的随机暂存目录；最小结构检查后用 `os.replace` 切换；
- 强制更新先生成微秒时间戳加随机后缀的唯一备份；最终切换失败时有恢复旧安装的分支；暂存目录在 `finally` 中清理。

残余 **P2**：安装器依赖发布前 validator 保证源包没有软链接，但安装时自身没有拒绝源树软链接；`copytree` 默认会跟随源软链接。建议在暂存前/后明确拒绝源与暂存树的任何软链接，避免未验证或被篡改的源码包带入外部文件。正常发布包当前静态检查无软链接。

### 6. 公开直接摘录与用户副本哈希：部分通过
