# Phase 5｜Agent Skill 架构审查

## 结论

当前包的认知架构、触发描述、章节覆盖、七模块路由和行为测试已经成形，但**不建议在修复 3 个 P0 前公开发布或让团队绑定真实私有资料**。P0 分别是：原书读取脚本可以输出整份 XHTML 正文、私有工作区没有落实“默认本人可见”的文件权限、安装器允许把目标目录放进源 Skill 内部而形成递归自复制。

本轮只做审查，没有修改 Skill 实现。

## P0｜发布前必须修复

### P0-1｜`epub_locator.py read` 绕过了短摘录版权护栏

**证据**：`read_item()` 接受任意 ZIP 成员名，读取整个成员，将全部文本写到 stdout；没有 XHTML 类型限制、锚点要求、字符上限或一次输出上限。README 与协议却声称“只显示必要短摘录”“不得连续导出正文”。当前实现只要对多个章节项重复调用，就可直接导出大量原书正文。

**修改**：删除公开的 `read` 命令，或改成硬限制的 `excerpt`：

- 只接受 `.xhtml` / `.html` / `.htm` 成员；
- 要求 `--anchor` 或精确定位条件；
- 默认输出很短，并设置不可被参数突破的硬上限（例如 500–1,000 个 Unicode 字符）；
- 输出定位、截断状态和版权提示；不提供“整项输出”开关；
- 对 ZIP 成员数量、单成员未压缩大小、压缩比和总处理量设置上限，拒绝异常 EPUB；
- 用合成 EPUB 做自动测试：普通短摘录通过，图片/OPF/超大成员/越界上限被拒绝。

### P0-2｜“私有工作区”目前只是命名私有，文件系统默认并不私有

**证据**：临时实测得到工作区与 `people/` 为 `drwxr-xr-x`，企业配置文件为 `-rw-r--r--`。同机其他账号可读取；同一共享账号下更无法做到“个人能力档案仅本人可见”。这与 SKILL 和 README 的默认隐私承诺冲突。

**修改**：

- POSIX 默认将私有根目录及个人目录设为 `0700`，敏感文件设为 `0600`；创建时使用安全 umask，并在完成后校验实际权限；
- 不要把所有成员的个人档案初始化到一个共享账号可读的同一根目录。默认给每位成员独立私有根，或要求企业接入明确的 ACL/身份系统；
- 团队共享案例与个人学习档案应是两个权限域。需要协作时提供显式 `--shared`/ACL 配置，而不是放宽默认值；
- Windows 或不支持 POSIX 权限的环境必须显示“未落实访问控制”，不得输出“已私有”的成功提示；
- 增加权限回归测试，至少验证 POSIX 目录/文件 mode。

### P0-3｜安装目标位于源目录内部时会递归复制自身

**证据**：`install.py` 只拒绝 `destination.resolve() == SOURCE_DIR`，未拒绝 `destination` 是 `SOURCE_DIR` 的后代。例如把 `--target-root` 指向 Skill 内的子目录，`copytree(SOURCE_DIR, destination)` 会在复制过程中看到新建目标并可能递归增长，造成磁盘/路径耗尽。

**修改**：在任何 `mkdir`/`rename`/`copytree` 前同时做规范化路径检查，至少拒绝 `destination` 位于 `SOURCE_DIR` 内；对符号链接解析后的路径也应用同一检查。增加隔离测试：目标等于源、位于源内、通过 symlink 指回源，三者都应在 dry-run 和 apply 前返回非零且不创建文件。

## P1｜应在 v0.1.0 发布前修复

### P1-1｜OpenAI YAML 的短描述不满足长度约束

`interface.short_description` 当前为“以《营销管理》第16版搭建可执行的企业营销系统”，按 Unicode 字符计数为 23，低于 `openai_yaml.md` 要求的 25–64 字符。改成至少 25 字符的准确描述，例如“以《营销管理》第16版搭建可执行的企业级营销管理系统”。其余字段正确：字符串有引号，品牌色格式正常，默认 prompt 含显式 Skill 名，隐式调用策略与用户需求一致。

### P1-2｜关键路由资源没有可发现入口

静态反向链接检查显示 `modules/00-router.md` 没有从 `SKILL.md` 或 README 链接；它正是“问题跨模块、层级不清、完整诊断”时应读的文件，却无法按 Skill Creator 的渐进披露原则被可靠发现。`templates/extension-manifest.md` 和 `templates/review-and-knowledge-promotion.md` 也只被脚本字符串引用，没有运行时 Markdown 路由。

**修改**：

- 在“选择主模块”前添加一句：跨模块、层级不清或完整体检时读取 `modules/00-router.md`；
- 在扩展方法获得同意后链接扩展清单模板；
- 在知识晋级处链接复盘与知识晋级模板；
- 不要因此把这些文件内容复制回 `SKILL.md`。

### P1-3｜正式记录与聊天呈现混在一起，已导致过度加载和过长输出

Phase 4 最终盲测记录显示执行者读取了 36 个文件，回答远长于日常首轮咨询需要。根因是“诊断/决策即正式咨询、正式咨询自动建档”容易被解释为“必须把固定记录的全部字段都展示在聊天里”。

**修改**：明确分离两个交付面：

1. 对话默认先显示“判断、致命缺口、2–4 个选项、下一步”四块简版；
2. 完整固定字段追加到私有案例记录；只有用户要求查看、教学模式或需要签批时才展开全文；
3. 默认只读主控、一个主模块、该模块深度工作流和直接相关章节；研究台账、测试、示例不得在普通咨询中加载；
4. 跨模块时先用路由器缩小范围，不为证明“系统性”一次读取全书。

这项修改不应删除标准化记录要求，只改变“保存完整”与“首屏展示完整”的耦合。

### P1-4｜公开包的版权口径内部不一致

协议和 README 说只有绑定合法本地原书后才显示短摘录，但 `references/research/01-writings.md` 已公开放入数条原书直接短摘录；`book-map.md`、`source-registry.md`、`07-book-extraction-audit.md` 还公开保存了用户提供 EPUB 的 SHA-256 指纹。短摘录本身数量不大，但实现与声明不一致，且哈希属于用户特定源文件的无必要指纹。

**修改**：按已确定的“本地原书为可选增强”策略统一口径：公开运行包只保留原创转述、章节/概念定位；把直接摘录改成转述或移到不随发布包分发的私有研究区；把原 EPUB 哈希移到私有索引，不在公开知识地图和来源注册表发布。若产品方决定公开保留极少量引文，则必须同步修改声明、逐条核对必要性和来源定位，不能继续声称“只有本地绑定后才有摘录”。

### P1-5｜EPUB 兼容性与资源上限不足

索引器只支持 NCX；纯 EPUB 3 常使用导航文档而没有 NCX，会直接失败。它还用 `epub.read_bytes()` 把整本书载入内存，并对目录引用成员逐个解压读取，没有总量/压缩比上限。

**修改**：通过 `META-INF/container.xml` 找 OPF，再解析 manifest/spine/nav；支持 NCX 与 EPUB 3 nav 两条路径。文件哈希改为流式计算。对成员数、文件大小、压缩比和累计解压量设合理上限，并为 NCX-only、nav-only、损坏包、压缩炸弹样本建立测试。

### P1-6｜`--force` 安装不是原子更新

当前流程先把可用安装重命名为备份，再直接 `copytree` 到最终路径；复制中断会留下“只有备份、没有活动 Skill”的状态。同一秒两次强制更新还可能撞备份名。

**修改**：先复制到同文件系统临时目录，完成验证后再原子切换；备份名用高精度时间加随机后缀，切换失败自动恢复原安装。安装完成后运行最小结构验证再报告成功。

### P1-7｜验证链没有自包含地覆盖发布约束

自带验证器能通过，但没有解析 `agents/openai.yaml`、没有检查 UI 描述长度、没有测试脚本运行与权限、没有测试递归安装和受限摘录。官方 `quick_validate.py` 又因宿主缺 `PyYAML` 无法运行。

**修改**：

- 在测试说明或开发依赖中明确官方验证需要 PyYAML，并在可复现环境中真正跑通；不要把当前失败写成“官方验证通过”；
- 扩展包内 smoke test，覆盖安装到临时目录、工作区权限、EPUB 摘录上限、OpenAI YAML 字段、所有相对链接；
- 每次评测保存运行清单：Skill `VERSION`/内容哈希、模型与推理配置、日期、输入 prompt、允许读取文件、原始输出、评分者和评分时间；
- 保持 `scenario_prompt.py` 的“生成后再揭示断言”设计，这是正确的。

## P2｜后续优化

1. **发布包与源码包分层**：安装器目前连 `tests/results`（约 120K）和研究台账（约 240K）一起复制。保留源码仓库中的审计材料，但生成运行时发布包时可排除 Phase 报告、历史测试输出和只供开发者使用的资料，减少误加载面。
2. **明确 Python 版本**：脚本使用 `Path | None`，实际要求 Python 3.10+；README 应明确版本和 Windows 权限差异。
3. **已有目录语义**：`init_workspace.py` 会向已有但无文件冲突的目录补写内容。可默认要求新/空目录，另设显式 `--merge`，避免用户误把无关目录当目标。
4. **索引覆盖保护**：`epub_locator.py index` 会覆盖已存在的输出文件。建议默认拒绝，显式 `--force` 时先备份。
5. **发布许可**：公开发布前需要项目所有者选择源码/内容许可；不要由构建代理擅自加入许可证。第三方版权声明不能替代本项目自己的授权条款。
6. **Claude Code 路径校验**：当前适配说明假设 `.claude/skills`。正式发布前应对照目标版本官方文档做一次真实安装/发现测试，并记录版本；不要仅以复制成功等同宿主已发现 Skill。

## 不应修改的部分

- 不要关闭隐式调用；用户要的是团队日常可发现的通用营销顾问，当前 `allow_implicit_invocation: true` 合理。
- 不要把 21 章、7 个深度工作流、模板和研究台账全部塞回 `SKILL.md`；现有三阶段披露方向正确。
- 不要删除首次身份透明声明、三位作者共同归属、Chernev 2019 的具体模型归属或身份受挑战时的拒绝规则。
- 不要弱化“致命缺口暂停确定性结论”、企业事实脱敏、外部检索先授权、扩展方法先同意、冲突不自动融合等硬边界。
- 不要把平台规则、跨境经验或外部学派写进第16版核心；继续保留“稳定核心 + 可插拔扩展”的隔离。
- 不要把企业工作区、个人能力档案、本地 EPUB 或索引打包回公共 Skill。
- 不要为了缩短输出而删除正式咨询记录；应将完整记录持久化与聊天简版展示分离。
- 不要用关键词命中率替代现有的行为场景与盲测；应在其上补充可复现运行元数据。

## 建议修复顺序

1. 先修复受限摘录、私有权限、递归安装三个 P0，并加隔离测试。
2. 修复 OpenAI 短描述、路由链接和简版/完整记录双输出契约。
3. 统一版权/哈希口径，补 EPUB 3 与资源上限。
4. 原子化安装，补完整发布 smoke test，并在具备 PyYAML 的环境跑通官方验证。
5. 最后再做运行包瘦身、许可决策和 Claude Code 真实宿主测试。
