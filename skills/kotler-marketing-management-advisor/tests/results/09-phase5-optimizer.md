# Phase 5｜Agent A Skill 优化审查

> 角色：Nuwa Phase 5 的 Skill 优化者
> 审查范围：`SKILL.md`、8 个短模块、7 个深工作流、12 个模板、Mock/安克示例、Phase 4 的 `01`—`08` 报告
> 变更边界：本轮未修改 Skill，只新增本报告。

## 总判断

核心正确性已经过关，不需要重做“第16版核心、六模型、十启发式、七工作流、三层 OS”。当前最弱的不是知识完整度，而是**运行时编排**：规则能推导出正确答案，却还没有足够强地约束“首轮读多少、答多少、什么时候展开、记录与聊天如何分离”。

最直接的证据是最终安克盲测：结论正确并通过全部密封断言，但执行者读取了 36 个文件，完整展开 7 个模块、7 个深工作流和大量章节，最终回答远长于日常首轮咨询。`SKILL.md:12` 已说“单轮默认只主动展开一个主框架”，`SKILL.md:130` 也说“不要一次加载全部章节”，但这两句没有转化为可执行的加载预算；反而 `modules/00-router.md:24` 的跨境路由和各模块的“深度运行前读取完整工作流”给了模型继续展开的理由。

第二个结构性问题是“标准化记录”同时承担了两个不同任务：一是后台形成完整、可审计的企业档案，二是向用户呈现当前回答。`SKILL.md:74/103`、`modules/00-router.md:35` 和 `formal-consultation-record.md` 很容易让任何诊断、计划或复盘都渲染成十段长表。固定结构本身是对的；需要拆开的是**存储结构**与**对话显示**，而不是删掉固定字段。

第三个问题是案例连续性目前只有自然语言原则。`case-and-knowledge.md:11` 已给出同案/新案规则，但私有工作区没有案例索引、案例主页、父版本或变更摘要，也没有“找不到可写工作区时不得声称已保存”的运行约束。因此“同一目标和指标持续汇入一案”还不是稳定能力。

下列建议按 P0/P1/P2 排序。P0/P1 均为发布前必须修；P2 是可选增强。

## P0｜必须修：建立首轮加载预算与分层回答契约

### P0-1 首轮加载预算

**问题**

- `SKILL.md:56-68` 只给模块路由，没有说明一次最多加载到哪一层。
- `SKILL.md:85` 在“解释或跨模块诊断”时同时指向完整六模型与十启发式文件。
- 跨境题天然跨模块，`modules/00-router.md:24` 容易被解释为七模块都要读。
- Phase 4 最终盲测因此读取 36 个文件；这不是偶发的回答风格问题，而是缺少硬性编排规则。

**必须修改的位置**

1. 在 `SKILL.md` 的“判断用户意图与模式”之后加入“运行深度与加载预算”。
2. 改写 `modules/00-router.md:24`，从“七模块按缺口选择”提升为“先选一个主模块，只登记交叉检查，不自动展开”。
3. 把七个短模块首行的“深度运行前读取完整工作流”改成带触发条件的句子。
4. 明示 `examples/`、`tests/`、`references/research/` 不属于正常回答的运行时资料。

**建议写入的文本**

```markdown
### 运行深度与加载预算（强制）

- 首轮默认只读取 `SKILL.md`、一个短模块；路由不清或横跨三个以上模块时才读 `modules/00-router.md`。
- 需要快速启发式时先读 `cheatsheet.md`，不要首轮同时读取完整六模型、十启发式和七个深工作流。
- 跨境进入可增加 Ch20；只有安全/责任成为决策门时增加 Ch21。首轮最多展开两个短模块，其余只登记为“待交叉检查”。
- 仅当用户明确要求正式产物、已经选择进入该工作流，或当前上下文足以制定执行方案时，读取对应深工作流和模板。
- 只有需要解释具体概念、核验章节依据或处理争议时，读取最多两个直接相关章节；需要更多章节时先完成当前轮，再按需展开。
- 正常咨询不得读取 `examples/`、`tests/` 或 `references/research/`；它们只用于教程、验收与来源审计。
```

七个模块的统一句式建议改为：

```markdown
**主章**：……。首轮先用本短模块；只有用户要求完整工作流、已进入执行设计，或短模块不足以安全作答时，才读取[完整工作流]。
```

`modules/00-router.md:24` 建议改为：

```markdown
跨境市场进入先读 Ch20，并选一个当前最阻塞决策的主模块；其他模块只列为交叉检查。未完成主模块资料闸门前，不依章节顺序展开七个模块。
```

**不应采取的修法**

- 不要删除 21 章知识层、六模型或十启发式；问题是加载策略，不是知识过多。
- 不要把七模块合并成一个超长文件；这会破坏按需披露。
- 不要为了少读文件而降低安全、经济性、合法性和责任否决门。

**验收标准**

- 重跑 S07 时，首轮运行资料应从 36 个文件降到不超过 8 个，且不读取七个深工作流。
- 回答仍须命中核心进入缺口、选项和停止门，但不在首轮完整展开 7T、五道 Gate、全 RACI 与多章教学。
- 普通定位、定价或投放问题的首轮只加载一个短模块；用户选择继续后才进入深工作流。

### P0-2 默认首轮输出契约

**问题**

`SKILL.md:70-74` 直接从决策进入行动/RACI、指标、复盘和正式记录，缺少“先给负责人能消化的首屏，再按阶段展开”的硬边界。Phase 4 的 S01 因用户明确要求正式记录而长是合理的；S07 没有要求完整记录，却仍生成了 13 节完整方案，说明默认输出门槛不足。

**必须修改的位置**

- 在 `SKILL.md` 的“形成决策、行动与学习闭环”前增加默认首轮结构。
- 在 `modules/00-router.md` 的“正式输出”区分首轮、深度方案、正式记录三种交付。

**建议写入的文本**

```markdown
### 默认首轮只显示五件事

1. 一句初步判断；
2. 真正要做的决策、Goal 与分析单位；
3. 最重要的 1—3 个资料缺口，以及各自阻塞什么；
4. 若属于重大决策，给 2—4 个简要选项和条件式倾向；
5. 一个最高价值的下一步或阻塞问题。

首轮不默认展开完整 7T、RACI、指标树、全章证据和固定记录表。用户明确要求完整记录/方案/教学，或用户完成选择进入执行后，才展开相应层级。用户说“极简”“不要上课”时，显式格式要求优先于默认展示，但不改变证据、安全与记录纪律。
```

**验收标准**

- S07 首轮能在五个区块内完成；后续用户说“展开试点计划”才读取 W4/W6 深工作流并生成 RACI。
- S01 仍因明确要求“正式咨询记录”输出完整结构，不受压缩。
- `executive-mode` 保持“结论 + 一个关键问题 + 条件/停止逻辑”，不被自动记录表淹没。

## P0｜必须修：把“自动记录”与“对话渲染”分离

### P0-3 固定数据结构，弹性对话呈现

**问题**

- `SKILL.md:74/103` 要求正式咨询自动形成十段记录。
- `modules/00-router.md:35` 又要求先使用固定外壳。
- `formal-consultation-record.md:3` 要求不适用项写“不适用”。在连续咨询里，这会反复复制未变化内容、制造大量空表，并诱导模型把后台档案直接贴进聊天。
- 用户提出的“固定字段”要求是治理要求，不等于每轮都要把全部字段展示给用户。

**必须保留**

所有正式记录仍保留：问题与范围、上下文快照、资料缺口、书中依据与短摘录、事实与假设、营销决策板、用户最终选择、行动计划、负责人、指标、复盘时间、知识晋级状态。不要删字段。

**必须新增的运行规则**

```markdown
### 记录层与呈现层分离

- 正式咨询在可写私有工作区中始终更新标准记录；聊天默认只呈现本轮决策摘要和变化，不自动展示整张记录。
- 保存成功后只回报案例 ID、咨询版本、文件位置和本轮更新摘要；用户要求“展示完整记录”时才渲染全部字段。
- 每个固定字段使用四种状态之一：`本轮新增`、`继承自 <version>`、`待补/待决定`、`不适用（说明理由）`。禁止为填满模板而复制旧正文或编造内容。
- 没有可发现、可写的私有工作区时，不得声称已保存；标记为“待持久化”，先给紧凑记录摘要，并说明如何绑定工作区。
```

**模板级具体修改**

`formal-consultation-record.md` 元数据增加：

```markdown
- 记录阶段：接单 / 诊断 / 决策 / 执行 / 复盘
- 父咨询版本：
- 本轮变化：新事实 / 新假设 / 新选择 / 新行动 / 新结果
- 保存状态：已保存 / 待持久化
```

把模板开头改为：

```markdown
固定字段用于存储与审计，不要求在聊天中全部展开。连续咨询优先引用父版本并记录本轮增量；只有里程碑快照或用户明确要求时，才生成自包含完整版。
```

**验收标准**

- 同一案例的第二轮咨询不会再复制完整 5C、全部依据和整张决策板；未变化字段写“继承自 v1”。
- 用户说“只给极简决策”时，后台记录仍可更新，但聊天不显示十段模板。
- 没有工作区时，回答明确说“未保存”，而不是模拟一个不存在的文件路径。

## P1｜必须修：把顾问/学习从二选一改为可组合的模式状态机

### P1-1 任务模式与呈现深度分开

**问题**

`SKILL.md:26-30` 把“专业顾问模式”和“边做边学模式”写成二选一。真实用户经常需要“先替我做决定，再解释为什么”，或在同一案例中从学习切到执行。当前设计虽然允许切换，却没有说明模式是否持续、混合请求如何处理、一次解释多少，也容易把“学习”误当成另一条业务流程。

**建议替换为两轴状态**

```markdown
### 本轮模式

先内部确定两项，不必每次向用户报告：

1. 任务模式：`顾问` / `学习` / `顾问+学习`。
2. 呈现深度：`极简` / `标准` / `完整`。

- 用户明确说“不要上课、只给结论、完整教学”等时，以显式要求为准。
- 同时要求解决问题和理解方法时，使用“顾问+学习”：先给业务判断，再只解释本轮一个主概念，附一个简例或理解检查。
- 模式只改变解释密度，不改变 G-STIC、证据闸门、决策板和安全边界。
- 模式在同一案例中持续，直到用户显式切换或新任务明显改变；短暂追问“为什么”只为本轮增加教学侧栏，不重启全部流程。
- 意图足够清楚时自动匹配，不额外让用户选模式。
```

**验收标准**

- “帮我决定并顺便教会团队”先给结论，随后只解释一个主概念，不生成七章课程。
- 用户从学习模式说“现在给我董事会版”时，立即切换呈现深度，但沿用同一案例事实与决策状态。
- 第二轮继续咨询不重复身份声明、模式说明或全局框架。

## P1｜必须修：收紧最低资料闸门的作用域，避免“资料不足 = 只列清单”

### P1-2 致命缺口必须指向具体结论或动作

**问题**

`SKILL.md:52` 的规则总体正确：暂停确定性结论，但仍可设计选项和验证。`modules/00-router.md:29` 却写成“只给资料清单与验证设计”，比主规则更强，可能阻塞仍然安全可做的研究、样品测试、基线测量或可逆行动。Phase 4 的合格答案事实上采用了更好的做法：明确“致命于商业化，但不阻塞非销售研究”。应把这种行为写成硬规则。

**建议替换 `modules/00-router.md:28-30`**

```markdown
- 缺 Goal/成功基准：不排名最终方案；仍可帮助定义阶段 Goal、候选选项和需要减少的关键未知。
- 缺战略、安全、经济性或合法性关键事实：把缺口写成“致命于哪项结论/动作”，只暂停该结论或动作；仍输出当下可判定事项、可比较选项、验证设计和低暴露的可逆下一步。
- 首轮默认只问一个最可能改变选项排序的阻塞问题；确需并行收集时最多列三项，并逐项说明为什么重要、影响哪个判断。
- 上游可用假设但非致命：显式标注、设失败条件后允许小规模验证。
```

**建议在每个模块的“强制输入”前加入统一解释**

```markdown
“强制输入”是形成确定性结论所需，不是开始咨询的门票。缺失时先给可判定边界与补证路径，不要求用户一次填完。
```

**验收标准**

- S02 必须说“安全缺口阻塞商业投放，不阻塞非销售顾客研究和独立测试设计”。
- 缺 Goal 的用户仍得到阶段目标草案，而不是只有一张资料清单。
- 首轮不会连续抛出十个问题；默认只追问最影响判断的一项。

## P1｜必须修：把案例连续性从原则变成可执行的数据契约

### P1-3 增加案例匹配键、增量版本与工作区发现

**问题**

- `case-and-knowledge.md:9-20` 已明确同案/新案原则，但没有匹配字段、冲突处理和写入步骤。
- `init_workspace.py` 只创建空 `cases/` 与两个通用模板，没有 `cases/index.md`、`_case-template.md` 或工作区元数据。
- `formal-consultation-record.md` 没有父版本、变化原因和继承字段。
- 结果是：同一个营销问题多次咨询时，模型可能每次新建完整记录；也可能把已改变市场的任务错误追加到旧案。

**必须新增的案例契约**

```markdown
### 案例路由顺序

每次正式咨询保存前：
1. 读取案例索引，只比较用户有权限访问的案例。
2. 用四个字段建立案例身份：`核心 Goal`、`成功指标及口径`、`市场`、`核心决策对象`。
3. Goal 和成功指标不变，且市场与核心决策对象未实质变化：追加到同一案例。
4. Goal、市场或核心决策对象任一实质变化：新建关联案例，记录 `related_to`、分叉原因及继承/不继承的事实。
5. 归属不清时不静默决定；给出候选案例和差异，请决策人确认。
6. 所有更新追加版本，不覆盖旧建议；记录哪些新事实或假设导致判断变化。
```

**建议新增的私有文件结构**

```text
cases/index.md                 # case_id、Goal、指标、市场、决策对象、状态、更新时间
cases/_case-template.md        # 案例主页与身份字段
cases/<case-id>/case.md        # 稳定案例定义和当前状态
cases/<case-id>/consultations/ # 增量咨询事件
```

`_case-template.md` 至少包含：

```markdown
- case_id：
- parent_case / related_cases：
- 核心 Goal：
- 成功指标、口径与期限：
- 市场：
- 核心决策对象：
- 决策人：
- 当前阶段：
- 最新咨询版本：
- 分叉原因：
```

`init_workspace.py` 应创建案例索引、案例模板和一个私有 `workspace` 元数据文件；适配器必须说明运行时如何发现/绑定该目录。若未绑定，执行 P0-3 的“待持久化”规则。

**验收标准**

1. 同一品牌、同一美国市场、同一 Goal/指标的三次定位咨询持续追加到一个 case，版本为 v1/v2/v3。
2. Goal/指标相同但市场从美国变为德国时，必须新建关联 case。
3. 目标不变但新证据推翻旧定位时，追加变更而不覆盖旧版本。
4. 两个历史案例都可能匹配时，必须询问一次，不自行合并。

## P1｜必须修：定义“重大决策”，为轻量问题提供迷你决策板

### P1-4 不让所有问题都升级为大表

**问题**

`SKILL.md:72` 说重大决策默认使用营销决策板，但没有定义“重大”。容易出现两种漂移：要么任何问题都生成 13 列大表，要么真正高风险决策被随意短答。

**建议规则**

```markdown
满足任一条件视为重大决策：改变 Goal/目标市场/价值主张；承诺显著预算或跨部门能力；上市、扩张、退出或不可逆品牌承诺；涉及安全、合法性、责任或重大声誉风险；影响三个以上模块；用户明确要求正式决策板。

非重大问题使用“迷你决策板”：决策、2—3 个选项、成立条件、主要代价、下一验证。重大问题才读取完整 `marketing-decision-board.md`。
```

**验收标准**

- “标题 A 还是 B”在战略已定时不生成完整 13 列表。
- “是否进入美国高风险新品市场”稳定触发完整决策板与责任否决。
- “请给正式决策板”无论风险大小都服从显式请求。

## P1｜必须修：把专家人格的最小行为内核放进主文件

### P1-5 不依赖运行时读取表达研究文件

**问题**

角色语气在 `references/synthesis/04-expression-values-boundaries.md` 中定义得很好，但 `SKILL.md:141` 仅在“信息截止与具体局限”处链接它。正常顾问回答未必会读该文件，因此“教授型资深顾问”的行为可能退化为模板填表。Phase 4 的人工 dry-run 已表现良好，但尚未覆盖多宿主、多采样。

**建议把以下短内核放到 `SKILL.md` 模式段之后**

```markdown
### 顾问行为内核

- 像严谨、耐心、敢于质疑的教授型资深顾问：先给可行动判断，再解释依据。
- 质疑命题，不质疑人；优先揭示目标、证据、上游依赖和系统后果中的隐含假设。
- 宽泛问题先校准范围；具体问题先判断；不知道时明确“现在能判断什么、不能判断什么”。
- 默认一次只问一个最高价值问题，并说明它会改变哪项决定；不要把苏格拉底提问变成连续审讯。
- 案例只解释机制和迁移条件，不以名企或权威压过证据。
```

**验收标准**

- 顾问拒绝不可兑现定位时，先给业务判断与替代路径，不只背三道门。
- 用户观点证据薄弱时，提出一条可回答的关键质疑，不进行人格化批评。
- 顾问模式保持“判断—依据—反证/缺口—下一步”的稳定节奏。

## 建议的实施顺序

1. 先改 P0-1/P0-2：锁定首轮读取与输出；这是 36 文件/长回答的根因。
2. 再改 P0-3：让固定记录留在存储层，聊天按需渲染。
3. 然后实现 P1-2/P1-4：收紧闸门作用域并定义重大决策，防止“全阻塞”与“大表泛滥”。
4. 实现 P1-1/P1-5：稳定混合模式和专家行为内核。
5. 实现 P1-3：补案例索引、版本、分叉与工作区绑定，这是团队长期共同使用的基础。
6. 最后补 P2 回归与教程分轮；重跑 S01、S02、S05、S07、四个 voice snapshots 及新增 S11—S16。

## 最终保护线

优化过程中不应改变以下内容：

- 不删减“第16版核心 + 六模型 + 十启发式 + 七工作流 + 三层 OS”；
- 不把平台规则、实战打法或外部方法静默混入核心；
- 不放松安全、合法性、经济性、隐私、责任和身份归属边界；
- 不把四级成熟度改回百分制；
- 不取消营销负责人对品牌知识晋级的批准权；
- 不牺牲固定咨询字段，只将其与前台展示、连续版本和阶段状态正确分离。

应用以上 P0/P1 后，这套 Skill 会从“能推导出完整正确答案”进一步变成“首轮就像真正资深顾问：读得少、抓得准、问得少、先推动决定，并把长期组织记忆安静地留在后台”。
