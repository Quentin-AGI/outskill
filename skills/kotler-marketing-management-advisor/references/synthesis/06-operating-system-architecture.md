# Phase 2｜三层式营销管理操作系统架构

## 1. 总体结构

```text
L1 稳定核心 / 营销管理宪法
  ├─ 第16版章节知识地图
  ├─ 六个心智模型 + 十条决策启发式
  ├─ G-STIC 主控路由
  ├─ 来源、归属、隐私、伦理与身份边界
  └─ 可选本地 EPUB 增强

L2 可调用专业工作流
  ├─ W1 用户与市场洞察
  ├─ W2 细分与目标市场
  ├─ W3 品牌定位
  ├─ W4 产品与产品组合
  ├─ W5 定价与促销
  ├─ W6 渠道、沟通与投放
  └─ W7 营销团队与运行管理

L3 企业私有工作区 / 可插拔扩展
  ├─ 企业配置与事实库
  ├─ 个人能力档案（成员本人默认可见）
  ├─ 咨询记录与持续案例档案
  ├─ 待验证经验与已批准品牌知识
  └─ 行业、平台、企业经验和外部方法扩展（需授权/标来源）
```

L1 与 L2 随公开 Skill 发布；L3 由每家企业/每位用户在自己的工作区初始化，不随公共包共享。

## 2. 主控路由器

### 2.1 接收任意问题

用户可以直接问具体问题，不强制先完成全公司诊断。路由器先在内部判断：

1. 这是解释、咨询、决策、执行、监控还是复盘？
2. 分析单位是公司、业务、品牌、国家市场、细分、产品、渠道还是活动？
3. 位于 G、S、T、I、C 哪层？
4. 七大模块中谁主责，哪些是上游依赖或横向审查？
5. 是否需要当前外部事实；是否涉及企业隐私；原书是否足以覆盖方法？

### 2.2 最小信息原则

只补当前决策所需信息。完整营销体检在以下情况主动建议：

- 用户问题跨越三个以上模块；
- 同一症状反复发生但局部修复无效；
- 团队无法说清目标市场、价值主张或共同 Goal；
- 新品牌/新国家/重大增长转折；
- 营销负责人希望建立年度/季度系统基线。

体检不是门票。用户拒绝时，仍可在明确假设和边界下处理局部问题。

### 2.3 路由示例

| 用户问题 | 表面模块 | 必查上游/交叉 | 资料闸门 |
|---|---|---|---|
| “美国广告越来越贵怎么办？” | W6 投放 | W2 目标、W3 定位、W5 经济性 | 目标、增量、完整经济性、渠道任务 |
| “要不要做高端子品牌？” | W3/W4 | W1 洞察、W2 目标、W5 定价、W7 资源 | 目标细分、组合冲突、兑现能力、品牌架构 |
| “这个 SKU 要不要砍？” | W4 | W2/W3、W5、W6 | 真实贡献、顾客角色、品牌/渠道/服务影响 |
| “如何进入欧洲？” | CH20 跨境主路由 | 七模块按实际决策调用 | 国别、需要、合规、能力、进入方式与 3V |
| “营销团队该怎么分工？” | W7 | 当前 G-STIC 与瓶颈 | 目标、流程、权责、能力、指标与资源 |

## 3. 全公司营销体检

### 3.1 体检范围

体检按七个系统层而不是按部门清单：

1. 战略营销计划；
2. 市场与洞察；
3. 目标市场与价值战略；
4. 产品/服务/品牌/价格设计；
5. 沟通与销售；
6. 渠道与零售；
7. 增长、创新、忠诚、全球化和责任；
8. 横向检查组织、证据、控制和知识治理。

### 3.2 评级与排序

- 评级：缺失 / 初步建立 / 稳定运行 / 持续优化；
- 没有证据：资料不足，不评级；
- 每个评级附企业事实、更新时间和提供者；
- 输出只聚焦 1—3 个瓶颈；
- 排序以战略影响和模块阻塞为先，再看紧迫、风险、成本、可逆性与反馈速度。

## 4. 渐进式初始化

### Level 0｜零配置

用户提出问题即可使用。只读 L1 和相关 L2 模块，不写企业长期资料；需要时临时询问最小上下文。

### Level 1｜案例工作区

第一次正式咨询时创建案例档案和咨询记录。只保存本问题的上下文、事实、决策、行动与复盘。

### Level 2｜企业配置

出现多个案例或用户主动初始化时，建立企业目标、品牌/市场/产品/渠道、角色权限和来源登记；后续咨询复用但每次检查更新时间。

### Level 3｜组织学习

启动个人能力档案、跨案例模式、候选知识和负责人审批。只有使用到这一层才创建，不让新用户面对空目录和治理负担。

### Level B｜本地原书增强

用户绑定合法 EPUB 后建立本地私有索引，启用精准章节锚点和必要短摘录。没有原书时核心 Skill 仍可运行，但只使用公开包内原创提炼，不声称检索到原文。

## 5. 企业私有工作区逻辑模型

```text
company-profile/
  objectives.md
  market-brand-product-map.md
  source-register.md
  permissions.md

facts/
  customers/
  competitors/
  products/
  channels/
  organization/

cases/<case-id>/
  case.md                 # 目标与成功指标决定案例连续性
  consultations/          # 每次咨询固定外壳 + 条件模块
  decisions.md            # 决策、替代项、保留意见、版本
  actions.md              # 行动、RACI、指标、阈值
  reviews.md              # 追加式复盘

knowledge/
  hypotheses/
  observed-patterns/
  candidate-brand-knowledge/
  approved-brand-knowledge/

people/<member-id>/
  private-learning-profile.md
```

实际文件名和格式在 Phase 3 定义；这里固定的是数据边界和状态机。

## 6. 案例连续性与版本

### 同一案例

核心目标与成功指标不变，即使问题、假设、行动和结果多次变化，也追加到同一案例；记录每次咨询时间和版本。

### 新建关联案例

目标、市场或核心决策对象发生实质变化时，新建案例，并记录 `related-to`、分叉原因和继承/不继承的事实。

### 不覆盖历史

更新事实、修正建议或用户改变选择时追加新版本；不回写旧记录使它看起来“当时就知道”。

## 7. 知识晋级状态机

```text
待验证假设
  → 单次经验
    → 跨情境重复模式
      → 候选品牌知识
        → 营销负责人批准
          → 正式品牌营销知识
```

- 每次晋级附适用范围、反例、证据、日期、责任人和废止条件；
- 外部方法即使有效，也保持扩展来源身份；
- 与第16版冲突时并列展示，不自动重写核心；
- 负责人可以批准企业采用某扩展方法，但不能把它伪装成书中观点。

## 8. 可插拔扩展接口

扩展包至少声明：

| 字段 | 要求 |
|---|---|
| `extension_id/version` | 唯一名称与版本 |
| `scope` | 解决什么问题、不解决什么 |
| `source` | 作者/机构、URL/文件、日期、可信度 |
| `method_type` | 外部事实 / 企业经验 / 行业方法 / 平台规则 / 其他方法论 |
| `core_mapping` | 映射到 G-STIC、5C、3V、7T 或章节，但不改写它们 |
| `conflicts` | 与第16版或其他扩展的已知冲突 |
| `consent` | 是否需要用户明确同意；外部方法论固定需要 |
| `privacy` | 是否读取企业数据、能否联网、脱敏要求 |
| `expiry/review` | 时效、失效条件、复核日期 |

主控调用顺序：先用 L1 定义问题；若只缺当前事实，可自动查询并标注；若缺方法，说明边界并征得同意后才调用扩展方法。

## 9. 正式输出的双层呈现

### 顶层：决策摘要

让营销负责人快速看到：问题、资料闸门、关键诊断、决策板、条件式倾向、用户选择、行动和复盘。

### 按需展开：证据与教学

展开章节概念、短摘录、推理链、模板、反证、案例、学习解释和个人能力记录。用户无需为了获得一个决定而先读完整教材。

## 10. 构建阶段的包边界

Phase 3 预计形成：

- 一个轻量主控 `SKILL.md`；
- 第16版全书双索引与按章知识文件；
- 六模型/十启发式运行参考；
- 七个深度工作流及可填写模板；
- 证据、隐私、案例、知识晋级和扩展协议；
- Mock 品牌教程、五个变体、历史企业冻结测试；
- 可选 EPUB 定位脚本与跨 Codex/Claude Code 安装说明。

公开包不包含原始 EPUB、连续摘录、企业资料或个人档案。
