# 主控路由器

当问题跨模块、层级不清或用户要求完整诊断时读取本文件。

## 1. 先定位，不先解题

1. 分析单位：公司 / 业务单元 / 品牌 / 国家市场 / 细分 / 产品线或 SKU / 渠道 / 活动。
2. 用户意图：学习、诊断、决策、执行、监控、复盘。
3. G-STIC 层级：Goal、Strategy、Tactics、Implementation、Control。
4. 主模块与上游依赖；不要一次加载无关模块。

## 2. 路由

| 主要未知/选择 | 主模块 | 常见上游/交叉 |
|---|---|---|
| 为什么买/不买、需要什么证据 | W1 | Ch03–05，W2 |
| 服务谁、不服务谁 | W2 | W1，Ch20 |
| 为什么选择该品牌 | W3 | W1、W2、W4–W6 |
| SKU、新品、产品线 | W4 | W2、W3、W5–W7 |
| 定价、版本、促销 | W5 | W1–W4、W6 |
| 分销、零售、传播、投放 | W6 | W2–W5、W7 |
| 组织、权责、能力、指标 | W7 | 所有模块 |

跨境市场进入先读 Ch20，并只选择当前最阻塞决策的一个主模块；其他模块登记为交叉检查。未完成主模块资料闸门前，不依章节顺序展开七个模块。

## 3. 闸门与升级

- 缺 Goal/成功基准：不排名最终方案；仍可帮助定义阶段 Goal、候选选项和要减少的关键未知。
- 缺战略、安全、经济性或合法性关键事实：写清“致命于哪项结论/动作”，只暂停该项；仍给可判定边界、选项、验证和低暴露可逆下一步。
- 默认只追问一个最可能改变选项排序的问题；确需并行收集时最多列三项，并逐项说明影响哪个判断。
- 上游可用假设但非致命：显式标注后允许小规模、可逆验证。
- 三个以上模块同时失效或局部修复反复失败：建议使用 [全公司营销体检](../templates/company-marketing-diagnostic.md)。

## 4. 分层交付

- 首轮聊天：判断、决策/Goal、1—3个缺口、重大决策的简要选项/倾向、一个下一步。
- 深度方案：用户选择继续或要求完整方案后，才加载主模块深工作流与模板，形成行动/RACI、指标和复盘。
- 正式记录：后台保持完整固定字段；聊天默认只显示案例 ID、版本、保存状态和本轮变化。用户要求展示、教学或签批时才渲染全文。
- 无可写私有工作区时写“待持久化”，不编造文件位置。

重大决策使用 [营销决策板](../templates/marketing-decision-board.md)；非重大问题用迷你决策板。

## 5. 禁止

- 因“系统性”要求用户先填完所有资料；
- 用平台或活动替代战略；
- 同时加载全部章节/模块造成噪声；
- 在关键缺口存在时给确定性推荐；
- 把外部方法悄悄混入第16版。
- 为证明系统性而读取 `examples/`、`tests/`、研究台账或全部工作流。
